# 两阶段流程优化 - 同时显示与可切换

## 功能概述

LLM策略挖掘页面现在支持**两阶段同时显示**，用户可以在阶段二返回阶段一修改策略思想，重新生成策略代码。

## 改进内容

### 1. 使用 Tabs 同时显示两阶段

**之前的问题**：
- 阶段一和阶段二是互斥的（if-else结构）
- 一旦进入阶段二，就无法返回阶段一
- 用户如果想修改策略思想，只能点击"清空重新开始"，丢失所有进度

**现在的解决方案**：
- 使用 `st.tabs` 创建两个标签页
- 阶段一：📝 策略代码
- 阶段二：📊 回测参数
- 两个阶段同时可见，用户可以随时切换

### 2. 返回阶段一按钮

在阶段二添加了"⬅️ 返回阶段一修改策略思想"按钮：
- 点击后切换到阶段一的tab
- 不清除任何状态
- 可以修改策略思想，重新生成代码
- 阶段二的参数（品种、周期等）都会保留

### 3. 代码编辑器功能

在阶段一添加了可编辑的代码编辑器：
- 直接修改LLM生成的代码
- 点击"🔍 重新检验"进行沙箱检验
- 检验通过后代码自动更新
- 检验失败显示错误信息

### 4. 状态持久化

所有关键状态都通过 `session_state` 持久化：
- `val_idea`: 策略思想
- `val_generated_code`: 生成的策略代码
- `val_code_sandbox_ok`: 沙箱检验结果
- `val_symbols`: 测试品种
- `val_interval`: 数据周期
- `val_start` / `val_end`: 起止日期
- 等等...

切换页面或切换tab都不会丢失状态。

## 使用流程

### 流程一：首次生成

```
1. 阶段一：输入策略思想
   ↓
2. 点击"🧬 生成策略代码"
   ↓
3. 等待LLM生成代码（10-60秒）
   ↓
4. 审阅生成的代码
   ↓
5. 点击"✅ 确认代码，进入阶段二"
   ↓
6. 自动切换到阶段二tab
```

### 流程二：修改策略思想

```
1. 在阶段二，点击"⬅️ 返回阶段一修改策略思想"
   ↓
2. 自动切换到阶段一tab
   ↓
3. 修改策略思想
   ↓
4. 点击"🧬 生成策略代码"（重新生成）
   ↓
5. 审阅新代码
   ↓
6. 点击"✅ 确认代码，进入阶段二"
   ↓
7. 阶段二的参数（品种、周期等）仍然保留
```

### 流程三：编辑代码

```
1. 在阶段一，直接编辑代码编辑器中的代码
   ↓
2. 点击"🔍 重新检验"
   ↓
3. 沙箱检验：
   ├─ ✅ 通过 → 代码已更新，可进入阶段二
   └─ ❌ 失败 → 显示错误，继续修改
   ↓
4. 检验通过后，切换到阶段二进行回测
```

## 技术实现

### 后端API

添加了 `/strategy/draft/validate` 端点用于沙箱检验：

```python
@app.post("/strategy/draft/validate")
async def strategy_draft_validate(payload: Dict[str, Any]):
    """沙箱校验策略代码（用于前端编辑后重新检验）"""
    code = payload.get("code", "")
    ok, err, errors = compile_strategy(code, require_base="CtaTemplate")
    return {"ok": ok, "error": err, "errors": errors}
```

### 前端Tabs

使用 Streamlit 的 `st.tabs` 组件：

```python
# 使用 tabs 让两阶段同时可见
if _has_generated_code:
    tab1, tab2 = st.tabs(["📝 阶段一：策略代码", "📊 阶段二：回测参数"])
else:
    # 未生成代码时，只显示阶段一
    tab1 = st.container()
    tab2 = None

with tab1:
    # 阶段一的代码...
    pass

if tab2 is not None:
    with tab2:
        # 阶段二的代码...
        # 返回阶段一按钮
        if st.button("⬅️ 返回阶段一修改策略思想", width="stretch"):
            st.rerun()
```

### 状态管理

所有状态都通过 `session_state` 持久化：

```python
# 初始化状态
if "val_generated_code" not in st.session_state:
    st.session_state.val_generated_code = None

# 读取状态
code = st.session_state.val_generated_code

# 更新状态
st.session_state.val_generated_code = new_code

# 清除状态
del st.session_state.val_generated_code
```

## 沙箱检验规则

检验会检查以下内容：

1. **语法检查**：Python语法是否正确
2. **安全检查**：
   - 禁止导入危险模块（`os`, `sys`, `subprocess` 等）
   - 禁止使用危险函数（`eval`, `exec`, `open` 等）
   - 禁止访问危险属性（`__globals__`, `__builtins__` 等）
3. **结构检查**：
   - 必须继承 `CtaTemplate` 基类
   - 必须实现 `on_bar` 方法
4. **白名单导入**：只允许导入 `quantmind.strategy.base`, `quantmind.core.utility`, `numpy`, `pandas`, `math`

## 优势

### 1. 用户体验提升

- **不再丢失进度**：切换tab不会丢失任何状态
- **灵活修改**：可以随时返回阶段一修改策略思想
- **直观展示**：两阶段同时可见，流程更清晰

### 2. 功能增强

- **代码编辑**：可以直接修改LLM生成的代码
- **实时检验**：修改后立即进行沙箱检验
- **错误提示**：检验失败时显示详细错误信息

### 3. 状态持久化

- **跨页面保留**：切换页面不会丢失状态
- **跨tab保留**：切换tab不会丢失状态
- **会话恢复**：刷新页面后自动恢复上次状态
